# Signal Attenuation in Generative Data Synthesis

What survives, and what is distorted, when a dataset produced by a known weighted formula is
regenerated by a tabular generative model?

## Summary

The project has two halves that answer each other.

**A conventional supervised regression task.** Five model families — linear regression, elastic
net, k-nearest neighbors, random forest, and gradient-boosted trees — are tuned by stratified
five-fold cross-validation on 20,000 student records and compared on their ability to predict
exam scores.

| Model | CV RMSE | SE |
|---|---|---|
| Elastic net | 8.8534 | 0.0623 |
| Linear regression | 8.8534 | 0.0619 |
| Boosted tree | 8.8626 | 0.0558 |
| Random forest | 9.3250 | 0.0629 |
| K-nearest neighbors | 12.0347 | 0.0398 |

The two most flexible families finish last. The tuned elastic net selects the weakest penalty in
its grid, making it ordinary least squares; the boosted tree selects the shallowest tree depth on
offer. Testing RMSE of the selected model: **8.740** ($R^2 = 0.784$).

**A fidelity analysis that explains why.** The competition dataset is synthetic, generated from a
source dataset whose outcome is built from a documented weighted formula. Comparing the two at a
matched sample size of 20,000:

- **All 11 substantive regression coefficients shrink toward zero**, by 6.5% on average — and the
  result holds without standardisation (7.3%).
- The **ordering** of those effects is preserved exactly (Spearman = 1.000).
- Coefficients on the five signal-free predictors are **inflated**, averaging roughly 1.8 times
  what their own standard errors would predict under a true null.
- **Residual variance falls 18.7%**, so the synthetic data is *easier* to predict than the process
  it imitates — a linear model scores 8.83 on it against 9.80 on its source.

The practical implication: a model comparison run on data of this kind may understate the
advantage of flexible methods, while overstating how accurately the underlying problem can be
solved at all.

Section 6.6 of the report sets out the limitations, including the fact that the generative
relationship between the two datasets is an assumption rather than a documented fact.

## Reproducing the analysis

**1. Get the data.** Neither file is redistributed here; download both from Kaggle into `data/`:

| File | Source |
|---|---|
| `train.csv` | [Playground Series S6E1](https://www.kaggle.com/competitions/playground-series-s6e1) |
| `Exam_Score_Prediction.csv` | [Exam Score Prediction Dataset](https://www.kaggle.com/datasets/kundanbedmutha/exam-score-prediction-dataset) |

**2. Install the R packages.**

```r
install.packages(c("tidyverse", "tidymodels", "glmnet", "kknn", "ranger",
                   "xgboost", "corrplot", "vip", "ggrepel", "doParallel"))
```

**3. Run the scripts in order**, from the repository root:

```r
for (f in list.files("R", full.names = TRUE)) source(f)
```

Step 04 is the slow one, at roughly twenty minutes on twelve cores. Everything else finishes in
seconds. All results are cached to `results/*.rds`, so the report knits without recomputing them.

**4. Knit `final_project.Rmd`.**
